# 测试驱动开发（TDD）

严格遵循红-绿-重构循环来编写代码。

## 工作流程

### 第一步：理解需求
1. 用 `grep` 和 `read_file` 了解现有代码结构和测试模式
2. 确认项目使用的测试框架（pytest / jest / vitest / go test / cargo test 等）
3. 查看现有测试的命名规范、fixture 用法、mock 策略

### 第二步：写失败测试（红）
1. 为目标行为写一个测试用例
2. 测试命名要描述行为：`test_用户登录成功返回token` / `should return token when user logs in`
3. 运行测试，确认它因为功能未实现而失败（不是因为语法错误）
4. 确认失败信息是清晰的——错误信息就是你的"规范文档"

### 第三步：写最小实现（绿）
1. 写最简单的代码让测试通过——不要过度设计
2. 运行测试确认通过
3. 如果有多个测试用例，重复红绿循环

### 第四步：重构
1. 测试通过后，改善代码质量：提取重复、改善命名、优化结构
2. 每次重构后立即运行测试，确保仍然绿色
3. 重构不改行为，只改结构

## 测试用例设计

按以下顺序覆盖：
1. **正常路径**：最常见、最期待的输入和输出
2. **边界值**：空值、零、最大值、最小值、单元素、大数组
3. **异常路径**：非法输入、网络失败、权限不足、并发冲突
4. **回归测试**：Bug 修复时先写复现测试

## 注意事项
- 每个测试只验证一个行为
- 测试之间相互独立，不依赖执行顺序
- Mock 在边界处做（外部 API、数据库、文件系统），不要 mock 被测代码本身
- 测试是文档——好的测试名能说明函数做什么
