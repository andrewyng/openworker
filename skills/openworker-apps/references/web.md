## Product to build

For PDF Notes, upload a PDF, extract page-numbered text, create one session per document and reuse it for follow-up questions. Forward incremental answer text to the browser and inspect the final run status. Keep credentials and the harness in the server process/container, not in the browser.

The reference app supports text-based PDFs only (no OCR or image understanding). Preserve its size/page/text limits and parsing timeout. Page citations are generated by the model, not independently verified. App-side document expiry is separate from durable harness history retention.

## Deployment choice

Start with the managed subprocess in the application container. `npm run web` runs locally after the README setup. The Docker recipe requires a matching Linux helper; a macOS executable cannot be copied into a Linux image. Supply runtime secrets and writable state storage; use HTTPS at the ingress.

The reference app is one user per instance. Its shared application token and random document IDs are not a multi-tenant authorization design. For multiple users, implement login, owner-bound document/session lookup, quotas and retention before exposing a shared instance.

For a separately deployed harness service, read `docs/harness/guides/deployment.md` and `docs/harness/SERVICE-ARCHITECTURE.html`. Do not substitute service-cluster APIs for the local example without checking the current SDK interface and the product's requirements.

Verify upload rejection, isolated document contexts, streamed responses, follow-up questions and denied access. Use a configured live provider only when authorized; otherwise run the fixture and state that it does not evaluate answer quality.
