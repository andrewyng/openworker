# 系统化调试

遵循严格的五步调试法，避免盲目改代码。

## 第一步：复现
1. 确认能稳定复现问题。如果间歇性出现，记录触发条件。
2. 收集完整的错误信息：异常类型、堆栈跟踪、错误码、日志输出。
3. 记录环境信息：输入数据、系统状态、并发情况、最近变更。
4. 如果无法复现，先加日志/断点缩小范围，不要猜。

## 第二步：隔离
1. 读堆栈跟踪，定位错误发生的文件和行号。
2. 用 `grep` 搜索相关函数/变量，理解调用链。
3. 用 `git_log` 查看最近改动，确认是否是回归问题。
4. 二分法：通过注释/禁用代码块，缩小问题范围。
5. 如果是多文件交互，用 `explore` 子代理并行调查多个嫌疑点。

## 第三步：假设
1. 基于证据形成具体假设："X 为 null 是因为 Y 函数在 Z 条件下没初始化它"
2. 设计验证方式：加日志打印、写个最小复现测试、用断点检查
3. 如果假设不成立，回到第二步重新隔离
4. 不要同时改多处--一次验证一个假设

## 第四步：修复
1. 修复根因，不要修补症状（不要用 try-catch 吞掉错误）
2. 最小改动原则：只改导致问题的代码，不趁机重构
3. 如果根因在别处（上游调用者），修源头而不是下游打补丁
4. 加注释说明为什么这个修复是正确的（如果非显而易见）

## 第五步：验证
1. 运行复现步骤，确认问题已解决
2. 写一个回归测试，确保同样的问题不会再出现
3. 运行相关测试套件，确认没有引入新问题
4. 检查类似的代码路径是否也有同样的 bug

## 常见陷阱
- **缓存**：清缓存再试，确认不是旧代码在跑
- **环境差异**：本地能跑但 CI 失败？检查依赖版本、环境变量、路径差异
- **异步时序**：Promise/async 问题常常间歇出现，检查 race condition
- **隐式状态**：全局变量、单例、类静态属性、模块级变量被意外修改
- **浮点精度**：0.1 + 0.2 !== 0.3，金融计算用 decimal
