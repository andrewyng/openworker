# Flow Nexus challenges

Start from the official problem statement, constraints, and available test evidence.
Explain the solution and its complexity, then validate representative and edge cases
locally when possible. Treat an unavailable or unauthenticated Flow Nexus connection as
a stated blocker, never as a reason to invent challenge data or feedback.

Use only the connected MCP tools that concern challenge learning. Reading challenge data,
leaderboards, achievements, authentication status, or balance can inform the work.
Submitting or completing a challenge can affect credits or account state: present the
candidate and validation evidence first, and wait for explicit approval before that call.
