### 2. NET-NEW LEAD, BUT NOT YOUR RUNNING KERNEL — Linux 7.1-rc7 gfx1151 memory-op hang
**ON-FOCUS-adjacent / workstation-stack. Likelihood of breaking THIS box: LOW (you are not on the affected kernel).**

- The only genuinely *surfaced* new lead this run (via DuckDuckGo `web_search`, surfacing a June 2026 mailing-list post): a **regression in the AMDGPU driver on Strix Halo (gfx1151, Radeon 8060S)**, reported on the `amd-gfx` list 2026-06-12, where upgrading from **kernel 7.1.0-rc5 → 7.1.0-rc7** causes GPU-memory operations (`torch.empty()`, weight transfers in ComfyUI, PyTorch 2.11.0+rocm7.13) to hang indefinitely; downgrading back to 7.1.0-rc5 resolves it. The reporter bisected the break to `amdgpu_hmm.c` (König), `gfxhub_v12_0.c` (Kristóf), `gmc_v12_0.c` (Kasiviswanathan) and `amdgpu_gart.c` (Tom) patches between rc5 and rc7. (opened in full this run)
  - https://lists.freedesktop.org/archives/amd-gfx/2026-June/146652.html
- **Why it's low-likelihood for you:** this box is on **kernel 7.0.0-29-generic** — the 7.0 release line, *not* the 7.1-rc line the regression lives in. The regression is between rc5 and rc7 of the **7.1 development series**, so a 7.0.0-29 kernel does not contain the offending patches. **No break on this machine.** Carried here only as Strix-Halo kernel-regression awareness (and it does sit one level below the standing gfx1151 runtime risk). If/when the box is ever moved onto 7.1, this is the one to watch.
