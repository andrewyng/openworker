## 1. NEW — the ROCr AsyncEventsLoop busy-spin bug (TheRock #7051, flagged 2026-08-18) has a **second, same-family report**, and it names your exact kernel
**ON-FOCUS (workstation-stack). Likelihood: MEDIUM-HIGH — the bug class is now proven to bite more than your wheel's architecture, and the newest report is on your exact environment.**

- New report: **ROCm/legacy-rocm-build #6634** — "[gfx1201] ROCr AsyncEventsLoop busy-spins at 100% CPU after Wan 2.2 workload completion", **state=open, created 2026-08-20 16:13 UTC, 0 comments, no assignee**. I read the full body.
  - https://api.github.com/repos/ROCm/legacy-rocm-build/issues/6634 (opened; full report)
- Environment in that report — **Kernel: 7.0.0-29-generic, PyTorch 2.12.0, ROCm 7.14** — i.e. the **same kernel you run**, on a gfx1201. Profiling isolates 99.79% of the spinning thread's time to `rocr::core::Runtime::AsyncEventsLoop` in `libhsa-runtime64.so.1`, and a 5-second `strace -e ioctl` capture shows **zero ioctl calls** — pure userspace spin, per the reporter.
  - The reporter explicitly links it to "other AsyncEventsLoop reports" (ROCm/ROCm#6522, ROCm/rocm-systems#7860 — not opened by me; treat as leads).
- What this means for the picture I held on 08-22: the bug was previously scoped to your gfx1151 torch wheel family (TheRock #7051, ROCR 1.21; 7.14 production also spinning). A second, independent report on **different GPU gen, same ROCR runtime and same kernel** weakens the "gfx1151-specific driver bug" framing and strengthens the read that this is a **ROCr runtime bug affecting the wheel channel you're on**. If a one-full-core-at-100% symptom shows up after any GPU workload completes, the new repro details (perf → `AsyncEventsLoop`, strace shows no KFD) give a clean way to confirm.
- **TheRock #7051 itself is unchanged**: re-opened via API today — state=**open**, label `status: triage`, assignee **adityas-amd**, 4 comments, last updated **2026-08-13**. No fix in ~3 weeks. First flagged 2026-08-18, now in this state, no new movement since 08-22.
  - https://api.github.com/repos/ROCm/TheRock/issues/7051 (opened today)
