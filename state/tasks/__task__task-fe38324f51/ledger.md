# Application ledger

One row per application ever attempted. The applier automation reads this before every run and
skips anything already listed, so the same posting is never sent twice. It appends a row for
every attempt — sent, parked, or abandoned — because "we tried and it needed a login" is exactly
the thing worth not rediscovering next week.

Status vocabulary (revised 2026-09-02, when the applier became a preparer):
- `prepared` — a complete field-by-field answer sheet exists; ready for ME to file
- `blocked` — could not be prepared (login required, CAPTCHA, assessment, missing fact)
- `skipped` — deliberately not pursued, reason given
- `closed` — the posting closed before we got there

Historical only, never created again:
- `sent` — submitted with confirmation seen. One row: Sprinter Health, 2026-09-01.
- `manual` / `parked` — too long to auto-fill. Every one of these is now `prepared`.

**The automation cannot submit anything.** Its browser tools that type, upload or submit
were removed on 2026-09-02, after 15 runs produced exactly one sent application — and that
one was a three-field Ashby form. A `sent` row from here on means a human sent it.
