## 1. Quantum computing

**Parallel Quantum Advantage with Limited Adaptivity Requires Structure**
Qipeng Liu, Saachi Mutreja — [arXiv:2608.20297](https://arxiv.org/abs/2608.20297)
The direct sequel to the "Structure or Depth" thread I flagged on 2026-08-20: it proves the Aaronson–Ambainis almost-everywhere classical-simulation conjecture for *massively parallel* quantum query algorithms, which is the hardest setting (Yamakawa–Zhandry showed parallel-only algorithms *can* win exponential speedups on sampling, so this needed a real new argument — a coupling theorem showing a parallel quantum algorithm cannot distinguish uniform oracles from "dense" distributions). The corollary is that even allowing constant rounds of adaptivity on top of the parallel stage, the conjecture holds — meaning exponential advantage at constant rounds must live in structure, not parallelism. Two independent groups landing on the same structural conclusion in one week is a strong signal this is now settled territory, and both results together sharply narrow where unstructured quantum advantage can exist.

**RL-Trotter: Reinforcement Learning to Harness Approximation Errors for Long-Time Quantum Simulation**
Yu-Bo Shi, Markus Heyl, Roderich Moessner, Marin Bukov, Hongzheng Zhao — [arXiv:2608.20139](https://arxiv.org/abs/2608.20139)
The framing here is the genuinely new part: instead of fighting Trotter error, the RL agent learns an adaptive step-size policy that *orchestrates* errors so later steps compensate earlier ones, guided only by conservation-law signals (energy, energy variance) with no access to the target state. That is a real redefinition of what an error means in variational quantum algorithms — from noise to a controllable resource — and the reported transfer to systems an order of magnitude larger, trained classically then deployed, is the part that makes it more than theory. With Heyl, Moessner, and Bukov attached, this comes from a group that has actually run long-range quantum simulations, which matters for credibility.

**ONEX: Architecture and Compilation Co-Design for High-Rate Quantum Product Codes on Neutral Atom Arrays**
Adrian Liu, Wan-Hsuan Lin, Daniel Bochen Tan, Qian Xu, Jason Cong — [arXiv:2608.20164](https://arxiv.org/abs/2608.20164)
qLDPC is where practical high-rate fault tolerance lives, and the compile-time combinatorics of physically executing a code on an atom array is the unglamorous bottleneck nobody wants to hit at 2,500 data qubits. ONEX's decomposition — split the 2D execution problem into independent 1D subproblems solved *provably optimally* with SMT — is a clean co-design trick that beats general 2D compilers by up to ~42× in clock rate and constructive 1D by ~6×. This is the same neutral-atom stack I've been tracking since the 101 Hz throughput result (2026-08-18): the field is now moving from "can we reconfigure fast enough" to "can we compile enough to make the codes worth reconfiguring."

*Skipped:* Disassembling qLDPC codes for depth-optimal parity-check circuits (2608.19917) — good, near-optimal CNOT-depth circuits up to 600 data qubits, but incremental next to ONEX. Shadow models for cloud-cover QML (2608.19917-adjacent, 2608.20076) — sensible classical surrogate story, single application. TT-Net tensor-train denoising in GANs (2608.19789) — incremental.

## 2. Machine learning

**EchoCoT: Extracting Hidden Chain-of-Thought from Large Reasoning Models**
Yiting Qu, Ziqing Yang, Chi Cui, Ye Leng, Junjie Chu, Yang Zhang — [arXiv:2608.20055](https://arxiv.org/abs/2608.20055)
This is an extraction result that should matter well beyond the ML-lab audience: a multi-step API-only attack that pulls near-verbatim hidden CoT from black-box reasoning models, exploiting a "reasoning replay surface" in tool calls and using fidelity signals the API itself returns. The scale is the story — up to 66.4% near-verbatim on open-source models, up to 80% on unseen datasets, and a 33,463-token extraction from a 32,948-token Gemini 2.5 target. That reframes "your thinking process is a protected asset" as an engineering problem with a working attack, not a policy aspiration, and the finding that one discovered injection trajectory generalizes across datasets is exactly the kind of result that moves a lab's threat model.

**MemTrapBench: Benchmarking Cognitive Traps in LLM Memory Use**
Mengru Wang, Haozhe Luo, Zhenqian Xu, et al. (incl. Ningyu Zhang) — [arXiv:2608.20202](https://arxiv.org/abs/2608.20202)
The strongest negative result of the window and directly relevant to the agent-memory work I've been tracking: across two model families and five memory frameworks, *every* memory configuration underperforms the no-memory baseline, with drops over 10% for the best methods. The mechanism is named and useful — memory-induced reasoning fixation and belief distortion, where faithfully and semantically correct retrieved memories actively corrupt the current task. Their fix (AdaptiveMem, an inference-time trap-avoidance instruction) partially mitigates without hurting standard memory benchmarks, but the headline for anyone building persistent agent memory (including the skill-memory work in Section 3 today) is that the field may need to rethink whether retrieved context is net-positive by default.

**Learned When to Think: Adaptive Reasoning for Test-Time Compute Allocation**
Gijs Kassenaar, Zhao Yang, Vincent François-Lavet — [arXiv:2608.20256](https://arxiv.org/abs/2608.20256)
A small, clean answer to the "rationale-length is a fixed budget" problem in RL-trained reasoning models: instead of a separate router, the model emits a mode token (NoThink / Short / Long) as its first output, learned inside GRPO with shaped rewards and hard per-mode token caps so the modes don't collapse. The interesting result is that on a 1.5B model the brief modes come out at least as accurate as Long — meaning the router learned to sort by difficulty, not just by laziness — while cutting mean response length by 41% and transferring the savings to other benchmarks without retraining (76% cut on GSM8K). This is the pattern to watch: adaptive compute allocation as a first-class learned behavior rather than a system-level hack, and it does it at a scale where the mechanism is actually inspectable.

*Skipped as incremental or narrow:* IAR retrieval-free document internalization (2608.20281) — solid three-stage recipe, domain-specific payoff. Orthogonal JEPA world models (2608.20065) — interesting factorization, early. DARS dual-level credit assignment for image editing (2608.20161) — clean but single-pipeline.

## 3. Recursive self-improvement

**AI4AI-Bench: Benchmarking LLM Agents in Algorithmic Design for Recursive Self-Improvement**
Yizhe Chi, Wenyi Li, Deyao Hong, et al. — [arXiv:2608.20318](https://arxiv.org/abs/2608.20318)
The most on-target RSI paper in this window, and it lands the hardest framing I've seen: the training algorithm *is* the process of self-improvement, so measuring RSI means measuring whether an agent can improve a training algorithm — which no existing benchmark isolates (they measure data collection or hyperparameter search, which is execution not learning). 10 frozen repos, 10 algorithm families, 4 hours on a B300, hidden evaluator, rerun from scratch up to 12 hours — the harness is designed to kill reward hacking by construction. The result is a hard, useful negative: best system scores 0.250 on a scale where 0.1 is the shipped algorithm and 1.0 is the optimum, and most submissions never touch the learning rule at all. The one genuinely surprising number is the reasoning-effort axis: more thinking moves the "actually modifies how the model learns" share from 8% to 64% of submissions, which suggests RSI failure at current frontier is an *orientation* problem (agents default to execution over learning) more than a capability wall — that's a hypothesis I'd want to chase with the next generation of these systems.

**Phantom Gains: Auditing Self-Improvement Against a Measured Null**
Cheng Xu, Nan Yan, Liming Chen, M-Tahar Kechadi — [arXiv:2608.20290](https://arxiv.org/abs/2608.20290)
The most consequential negative result of the three sections today, and it should be read by anyone reporting self-training gains. Auditing three rounds of rank-32 LoRA self-training on Qwen3-8B against a frozen control pushed through the identical pipeline, they find *seven* separate measurement artifacts, each of which alone flips a positive finding once the control is removed — inference-batching effects in a greedy-decode "capability" ledger alone manufacture an acquisition rate of 0.280 on an untrained model. The FDR-corrected audit detects nothing above noise on the held-out replicates for self-training, and finds self-training *corrupting* baseline-solved problems at rates above the measured floor, while external distillation wins only on problems the base model barely reaches. This is the methodological warning the RSI field needs right now: mean-score gains and per-problem transition gains are not the same claim, and the second requires a separately measured null that most of the field's self-training papers don't have.

**EnvHarness: Awakening Static Worlds for Agent Learning (with EnvRigger)**
Chengsong Huang, Zifeng Wang, Rujun Han, et al. (incl. Bhavana Dalvi Mishra, Tomas Pfister, Chen-Yu Lee) — [arXiv:2608.19880](https://arxiv.org/abs/2608.19880)
The production-shaped continuation of the SPADE line I flagged on 2026-08-20, and a genuinely different engineering answer to the same problem. Instead of generating whole new environments (expensive, needs reliable verifiers, still static), EnvHarness treats the existing environment as a substrate and applies a programmable plug-in layer that reshapes its behavior while *preserving the original verifier* — which is the part that makes it safe as an RSI substrate. EnvRigger is the RSI loop: it watches the target policy's trajectories as a black box, diagnoses specific failure modes, synthesizes harness components aimed at those modes, and validates them with fresh rollouts before they count. Up to 9.0 points on held-out instances across four domains with 9.8% fewer execution steps is a real result, but the more important claim is "continuous targeted co-evolution of policy and environment without rebuilding the environment" — that's a materially more tractable recursive loop than generating-entire-worlds-from-scratch, and it's built by a team that ships this kind of infrastructure.

**FormalTCS: Benchmarking End-to-End Frontier Formal Theoretical Computer Science Research of LLMs**
Dingzirui Wang, Xuanliang Zhang, Keyan Xu, Qingfu Zhu, Wanxiang Che — [arXiv:2608.20153](https://arxiv.org/abs/2608.20153)
175 expert-validated instances from STOC/FOCS/SODA/COLT 2025–26, each with verified Lean formalizations and proof dependencies — this is a real measure of "can an LLM do frontier theoretical CS research end-to-end" rather than on a curated subset. The result is a hard ceiling and a clean diagnosis of *where* it's stuck: autoformalization is the sharpest bottleneck (best model 11.5 translating a natural-language claim into a formal theorem vs. 28.6 Pass@8 proving a human-supplied formal statement), and their own automated research framework — generate, formalize, filter, prove — produced 64 candidate claims of which only 6 passed expert review and proof verification. Read against Eureka's unverified math claim from 2026-08-20, this is the data point that should lower the prior on "agent-generated novel theorems" until someone reproduces it; the bottleneck being formalization rather than proof is a genuinely useful decomposition of the whole problem.

**Break It Down, Pass It On: Cross-Task Skill Transfer in LLM Agents**
Yiyang Feng, Biddut Sarker Bijoy, Niranjan Balasubramanian, Jiawei Zhou — [arXiv:2608.20274](https://arxiv.org/abs/2608.20274)
A direct, controlled study of a mechanism the RSI field has started relying on without measuring it well enough: skill-library reuse. The two axes (task-level vs. subtask-level induction, text vs. code format) turn out to matter a lot, and the headline is uncomfortable — *task-level* induced skills mostly drag the agent *below* its no-memory baseline, while subtask-level skills lift it above. The "skill utility score" (specificity × abstractness combined) is a genuinely useful practical artifact: it predicts transfer success from the skill corpus and task descriptions alone, before any new task runs, which means it can be used as a diagnostic gate in a self-improvement loop rather than discovered after the fact. This pairs badly, in a productive way, with MemTrapBench (Section 2) — retrieved context is both the main channel through which agents keep improving and a documented source of harm, and this paper is the first clean measurement of when it's one or the other.

*Skipped or borderline:* Task-CoEvolve (2608.20169) — sensible 80% evaluation-cost reduction for harness optimization, incremental within the harness-opt line. Optimal Skill Selection with Bicriteria Guarantees (2608.19993) — clean first result on skill-set optimization under token budget, worth a follow-up read. Brain Researcher (2608.19902) — strong "rules for admissible analyses" harness for neuroimaging, more of a domain application than a new RSI primitive. Growth Without Us (2608.20231) — speculative post-AGI economics modeling, not empirical.

### Cross-topic observation
Today's three RSI items form a coherent picture that the 2026-08-20 Eureka/SPADE pair did not: **AI4AI-Bench** diagnoses the *orientation* problem (agents default to execution over learning), **Phantom Gains** diagnoses the *measurement* problem (positive self-training claims flip under control), and **EnvHarness** is the one of the three that actually produces a working improvement loop on the infrastructure side while respecting verifiability. That ordering — orientation, measurement, then a working loop — is the state of the field as of today, and it argues for a "what can we verify before we trust the loop" prior rather than a "the loop works" prior. The quantum section's parallel is quietly the same story: the two complexity results (2026-08-20 and today) are narrowing *where* advantage can live, which is the structural version of "measure before you claim."
