# OpenWorker UX & Frontend Design Paradigm

When generating, modifying, or designing frontend code (HTML/CSS/JS) for `openworker`, you MUST adhere to the following UI architectural rules. This ensures the application remains a professional, high-telemetry environment tailored for AI Architects, rather than a basic consumer chatbot.

## 1. The Chat Timeline is for Orchestration, Not Data Dumps
- The main chat view should remain clean and high-level.
- **Never** render massive documents, long JSON payloads, or 500-line code snippets directly in the chat stream. 
- Use the chat to display inline **Swarm Graphs** (visual representations of parallel subagent execution) and compact notification cards.

## 2. Telemetry and Traceability First
- Provide deep observability into the agentic backend. 
- The right-hand sidebar must contain a **Telemetry Tab** to track Token Usage, API Latency, and Context Window files.
- Subagent nodes in Swarm Graphs must be interactive. Clicking them should open a **Subagent Trace Panel** (slide-over or modal) that displays the exact prompt, internal reasoning block, tool execution log, and raw output of that specific subagent.

## 3. The Artifact Split-View Pattern
- Any persistent document, plan, or codebase file generated by the agent is considered an **Artifact**.
- Artifacts MUST be displayed in a dedicated **Split-View Panel** (e.g., a 50/50 layout with Chat on the left, Artifact on the right).
- The Artifact Panel must support rich rendering (Markdown, syntax highlighting, diffs, Mermaid graphs).
- The Artifact Panel must include actionable UX elements (e.g., "Approve", "Execute", "Reject" buttons) anchored at the top or bottom of the view to facilitate Human-in-the-Loop workflows.
